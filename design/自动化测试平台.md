# AI 驱动的 UI 自动化测试平台 —— 完整设计与开发方案

> **目标读者**：其他 AI Code 工具（如 Claude Code、Cursor、Copilot）或开发者，阅读本文即可从零复刻出类似平台。
> 
> **核心理念**：以 Playwright 为基座，融合内网多模态大模型（VLM）与 MCP 协议，实现「自然语言驱动、视觉理解、脚本自愈」的 UI 自动化，并构建可视化测试平台。

## 一、系统全景

### 1.1 整体定位

这是一个**纯测试客户端**，不含被测应用源码。测试驱动的是远程站点（内网部署），通过 Playwright 操控 Chromium 浏览器完成 UI 自动化。

与传统 UI 自动化框架的本质区别：

| 维度 | 传统自动化 | 本平台 |
|------|-----------|--------|
| 用例编写 | 代码脚本（XPath/CSS） | 中文自然语言步骤 |
| 元素定位 | 固定选择器，改版即断 | 三级自愈（知识库→语义→VLM视觉） |
| 断言方式 | 代码断言 | VLM 视觉断言（"确认页面正常展示"） |
| 维护成本 | 高（前端重构=用例大面积失败） | 低（自愈+视觉定位抗变更） |
| 用例生成 | 手工编写 | AI 生成（需求描述/页面探索/录制翻译） |

### 1.2 五层架构

## 二、技术选型

### 2.1 后端技术栈

| 组件 | 选型 | 理由 |
|------|------|------|
| Web 框架 | **FastAPI + uvicorn** | 与引擎同为 Python，可直接 import core/；原生支持 WebSocket |
| 浏览器自动化 | **Playwright (同步 API)** | 比 Selenium 更快更稳；同步 API 适合线程模式 |
| ORM | **SQLAlchemy 2.0** | 声明式映射，支持多数据库后端 |
| 数据库 | **MySQL（首选）+ SQLite（回退）** | MySQL 用于正式部署，SQLite 保证无依赖也能本地跑 |
| 大模型客户端 | **自研 OpenAI 兼容客户端** | 零依赖（stdlib urllib），支持 chat/function call/多模态图像 |
| 密钥加密 | **Fernet (AES-128-CBC + HMAC)** | 对称加密，API Key 加密存库 |

### 4.2 浏览器管理 (core/browser.py)

**设计思路**：上下文管理器模式，一次启动复用整个会话。

```python
# 关键实现模式
@contextmanager
def launch_context():
    """
    启动 Playwright 浏览器上下文，yield (context, page)。
    
    关键点：
    1. 无头/有头由 PW_HEADLESS 环境变量控制（优先）或 config.yaml
    2. 注入 Fullscreen API mock（无头模式下 requestFullscreen 静默失败）
    3. viewport 从配置读取
    4. 超时从配置读取
    """
    with sync_playwright() as pw:
        browser = pw.chromium.launch(headless=is_headless())
        context = browser.new_context(
            viewport={"width": w, "height": h},
            ignore_https_errors=True,
        )
        context.set_default_timeout(timeout)
        context.set_default_navigation_timeout(nav_timeout)
        page = context.new_page()
        page.add_init_script(FULLSCREEN_MOCK_JS)
        try:
            yield context, page
        finally:
            browser.close()
```

### 4.3 页面对象基类 (core/base_page.py)

**设计思路**：封装所有等待和交互逻辑，严禁 `time.sleep`。

```python
class BasePage:
    def __init__(self, page: Page):
        self.page = page

    def wait_visible(self, selector, timeout=None):
        """等待元素可见（状态等待，非sleep）"""
        self.page.locator(selector).first.wait_for(state="visible", timeout=timeout)

    def wait_hidden(self, selector, timeout=None):
        """等待元素消失"""
        self.page.locator(selector).first.wait_for(state="hidden", timeout=timeout)

    def wait_loading_disappear(self, timeout=8000):
        """等待 loading 指示器消失（兼容 Ant Design 和 Element UI）"""
        for sel in [".ant-spin", ".el-loading-mask"]:
            try:
                loc = self.page.locator(sel)
                if loc.count() > 0:
                    loc.first.wait_for(state="hidden", timeout=timeout)
            except:
                pass

    def safe_click(self, selector) -> bool:
        """多级降级点击：正常→等动画→JS点击→force点击"""
        # 1. 等待可见
        # 2. 等待可能的 modal 动画结束
        # 3. 尝试正常 click()
        # 4. 失败则 JS evaluate click
        # 5. 再失败则 force=True
        ...

    def health_check(self) -> dict:
        """UI 健康检查：无报错弹窗、无破图、非白屏"""
        return {
            "healthy": not has_errors and not has_broken_images and not is_blank,
            "error_toast": ...,
            "broken_images": ...,
            "blank_body": ...,
        }
```

### 4.4 主页面导航 (core/main_page.py)

**设计思路**：语义定位 + 面包屑到达校验，绝不依赖 hash 类名。

```python
class MainPage(BasePage):
    def nav_to(self, top_menu: str, sub_menu: str):
        """
        两级导航：
        1. 点击顶部菜单（用 :text-is('菜单名'):visible 避免命中隐藏span）
        2. 等待侧边栏子菜单出现
        3. 点击子菜单
        4. 用面包屑校验是否真正到达目标页（避免假通过）
        """
        # 点一级菜单
        self.page.locator(f':text-is("{top_menu}"):visible').click()
        # 等待侧边栏渲染
        aside = self.page.locator("aside")
        aside.locator(f':text-is("{sub_menu}")').wait_for(state="visible")
        # 点二级菜单
        aside.locator(f':text-is("{sub_menu}")').click()
        # 面包屑到达校验
        self._verify_breadcrumb(top_menu, sub_menu)

    def _verify_breadcrumb(self, top, sub):
        """面包屑校验：确认真正到达了目标页"""
        bc = self.page.locator(".ant-breadcrumb, .el-breadcrumb")
        bc.locator(f':has-text("{sub}")').wait_for(state="visible", timeout=5000)
```

### 4.5 大模型客户端 (core/llm_client.py)

**设计思路**：零外部依赖（仅 urllib），兼容任何 OpenAI 协议接口。

```python
class LLMClient:
    """OpenAI 兼容的 LLM 客户端。"""
    
    def __init__(self, base_url, api_key, model, timeout=60):
        self.base_url = base_url.rstrip("/")
        self.api_key = api_key
        self.model = model
        self.timeout = timeout

    def chat(self, messages: list[dict], tools=None, tool_choice=None) -> dict:
        """
        发送聊天请求。
        - messages: [{"role": "system/user/assistant", "content": "..."}]
        - tools: function call 工具定义列表
        - tool_choice: 强制调用某工具 {"type":"function","function":{"name":"..."}}
        - 返回 assistant message（含 tool_calls 如有）
        """
        body = {
            "model": self.model,
            "messages": messages,
            "temperature": 0.1,  # 低温度保证确定性
        }
        if tools:
            body["tools"] = tools
            body["tool_choice"] = tool_choice or "auto"
        return self._post("/chat/completions", body)

    def vision(self, prompt: str, image_base64: str) -> str:
        """
        多模态图像理解。
        - 图像以 base64 编码内联传入
        - 返回模型文本回复
        """
        messages = [{
            "role": "user",
            "content": [
                {"type": "text", "text": prompt},
                {"type": "image_url", "image_url": {
                    "url": f"data:image/jpeg;base64,{image_base64}"
                }}
            ]
        }]
        return self.chat(messages)["content"]


def get_client() -> LLMClient:
    """
    获取 LLM 客户端实例。
    优先级：DB 默认 LLMConfig > config.yaml llm 段
    """
```

### 4.6 VLM 视觉能力 (core/vision.py)

**设计思路**：截图→大模型看图→返回坐标或判断结果。

```python
def locate(page, description: str) -> dict | None:
    """
    视觉定位：用 VLM 在页面上找到描述所指的元素。
    
    流程：
    1. 截图（缩放到 max 900px 宽，JPEG 压缩降 token）
    2. 发 VLM：「在这个页面截图中，找到"{description}"的位置，
       返回归一化坐标 {"x": 0.0~1.0, "y": 0.0~1.0}」
    3. 坐标反查 DOM：page.evaluate(document.elementFromPoint(x, y))
    4. 从命中元素生成稳定选择器（优先 id > data-* > text，排除 hash 类名）
    5. 验证选择器有效性
    """
    screenshot = _take_scaled_screenshot(page, scale=0.4, max_width=900)
    response = vlm_client.vision(LOCATE_PROMPT.format(desc=description), screenshot)
    coords = _parse_coordinates(response)
    element_info = page.evaluate(f"document.elementFromPoint({x}, {y})")
    selector = _generate_stable_selector(element_info)
    return {"selector": selector, "strategy": "vlm"}


def assert_visual(page, claim: str) -> dict:
    """
    视觉断言：判定当前页面是否满足描述。
    
    流程：
    1. 截图（同上缩放压缩）
    2. 发 VLM：「观察这个页面截图，判断以下描述是否成立："{claim}"。
       返回 JSON: {"pass": true/false, "reason": "判断理由"}」
    3. 解析结果
    """
    screenshot = _take_scaled_screenshot(page)
    response = vlm_client.vision(ASSERT_PROMPT.format(claim=claim), screenshot)
    return _parse_verdict(response)  # {"pass": bool, "reason": str}
```

### 4.7 三级自愈定位 (core/self_healing.py)

**这是本平台最核心的创新点之一。**

```python
def find_element(page, anchor: str, locator_hint=None) -> dict | None:
    """
    三级定位，找到返回 {selector, strategy}，找不到返回 None。
    
    anchor: 元素的自然语言描述（如 "设备监控" "搜索按钮"）
    locator_hint: 用户手动指定的精确定位（优先于三级）
    
    三级策略：
    ┌─────────────────────────────────────────────────────────────┐
    │ ① Locator Store（知识库命中）                                 │
    │    查 DB locator 表，anchor 匹配则取 selector 直接用           │
    │    命中：hit_count++，直接返回（零成本、最快）                  │
    │    未命中/选择器失效：fail_count++，进入②                      │
    ├─────────────────────────────────────────────────────────────┤
    │ ② 语义定位（Playwright 文本/角色选择器）                       │
    │    尝试以下选择器（按优先级）：                                 │
    │    - :text-is("anchor"):visible                              │
    │    - :has-text("anchor"):visible                             │
    │    - role=button[name="anchor"]                              │
    │    - role=link[name="anchor"]                                │
    │    - role=menuitem[name="anchor"]                            │
    │    命中：回写知识库（selector + strategy=semantic），返回       │
    │    全部未命中：进入③                                          │
    ├─────────────────────────────────────────────────────────────┤
    │ ③ VLM 视觉定位（截图→坐标→反查DOM→生成选择器）               │
    │    调 vision.locate(page, anchor)                            │
    │    命中：回写知识库（strategy=vlm），返回                      │
    │    未命中：返回 None（判为功能缺陷，不伪造！）                  │
    └─────────────────────────────────────────────────────────────┘
    
    核心原则：自愈 ≠ 掩盖 Bug
    - 仅「选择器漂移」（元素在但原选择器失配）触发自愈
    - 元素确实不存在 → 返回 None → 上层报功能缺陷
    """
```

**知识库回写逻辑**：

```python
def _store_save(anchor, selector, strategy, hit: bool):
    """
    成功定位后回写知识库：
    - 新 anchor → INSERT
    - 已有 anchor → UPDATE selector/strategy
    - hit=True → hit_count++
    - hit=False → fail_count++（旧选择器失效时）
    
    效果：平台越跑越稳，相同元素后续直接走①知识库命中
    """
```

## 五、AI Planner 设计 (platform/worker/planner.py)

### 5.1 核心思路

用 LLM 的 **function call** 能力把一句中文步骤解析为结构化动作，而非让 LLM 直接操作浏览器。

### 6.2 执行流程

```python
def run_case(case: dict, emit: EventCb, cancel: threading.Event = None):
    """
    执行一条用例。
    
    流程：
    1. 启动浏览器（无头 + CDP 投屏）
    2. 开启 CDP Page.startScreencast（实时推帧）
    3. 逐步执行：
       a. 解析步骤（Planner LLM / 规则式回退）
       b. 分发动作（login/navigate/click/assert/health_check）
       c. 发 step 事件（步骤开始/完成/失败）
       d. 发 frame 事件（当前画面帧）

    5. 关闭浏览器
    """
```

### 6.3 CDP 实时投屏

```python
def _start_screencast(page, emit: EventCb):
    """
    开启 CDP 投屏。
    
    原理：
    - CDP Page.startScreencast 让 Chromium 主动推 JPEG 帧
    - 无头浏览器也支持（不需要物理/虚拟显示器）
    - 每帧必须回执 ack，否则 Chromium 停止推送
    
    关键代码：
    cdp = page.context.new_cdp_session(page)
    cdp.send("Page.startScreencast", {
        "format": "jpeg",
        "quality": 60,
        "maxWidth": 1440,
        "everyNthFrame": 1
    })
    cdp.on("Page.screencastFrame", lambda params: _on_frame(params, cdp, emit))
    
    帧回调：
    def _on_frame(params, cdp, emit):
        emit("frame", {"data": params["data"]})  # base64 JPEG
        cdp.send("Page.screencastFrameAck", {"sessionId": params["sessionId"]})
    
    补帧策略：
    - 页面导航跳转时 CDP 可能丢帧
    - 每步执行完后主动 page.screenshot → emit("frame")
    - 执行结束前也补一帧
    """
```

### 7.3 线程桥接设计 (run_manager.py)

**核心问题**：Playwright 同步 API 不能在 asyncio 事件循环线程中运行。

**解决方案**：后台线程 + 线程安全队列 + WebSocket 消费。

```python
class RunSession:
    """一次执行会话：线程跑 Worker，队列桥接事件到 WebSocket。"""

    def __init__(self, case: dict, run_id: int):
        self.queue = Queue(maxsize=500)  # 线程安全的有界队列
        self.cancel_event = threading.Event()
        self.thread = threading.Thread(
            target=self._run_in_thread,
            args=(case, run_id),
            daemon=True,
        )

    def _run_in_thread(self, case, run_id):
        """后台线程：调用 runner.run_case()，事件通过 queue 传出。"""
        def emit(kind, payload):
            self.queue.put_nowait({"kind": kind, **payload})

        try:
            runner.run_case(case, emit=emit, cancel=self.cancel_event)
        except Exception as e:
            self.queue.put_nowait({"kind": "done", "status": "error", "error": str(e)})

    def start(self):
        self.thread.start()

    def cancel(self):
        self.cancel_event.set()


# WebSocket 端点
@app.websocket("/ws/runs/{run_id}")
async def ws_run(websocket, run_id):
    session = get_session(run_id)
    await websocket.accept()
    while True:
        try:
            event = await asyncio.get_event_loop().run_in_executor(
                None, session.queue.get, True, 0.1  # 0.1s 轮询
            )
            await websocket.send_json(event)
            if event["kind"] == "done":
                break
        except Empty:
            continue
```

## 十五、给其他 AI Code 的实现指引

### 15.1 从零开始的建议顺序

1. **先搭 core/config.py + core/browser.py**：能启动浏览器、打开页面
2. **再搭 core/base_page.py + core/login_page.py**：能自动登录
3. **添加 core/main_page.py**：能导航到各个页面
4. **搭建 platform/backend/main.py + db.py**：API 骨架 + 数据库
5. **搭建 platform/frontend/ 骨架**：Vue + Vite + Element Plus + 路由
6. **实现 runner.py 基础执行 + CDP 投屏**：用例能跑、画面能看
7. **实现 self_healing.py 三级定位**：元素能自愈
8. **实现 llm_client.py + planner.py**：AI 解析中文步骤
9. **实现 vision.py**：VLM 视觉定位和断言
10. **实现 script_compiler.py**：NL → 脚本编译
11. **实现各种 AI 生成方式**：generator / explorer / recorder

### 15.2 核心创新点（必须实现）

1. **三级自愈定位**：知识库命中 → 语义定位 → VLM 视觉定位，成功后回写知识库
2. **CDP 无头投屏**：无头 Chromium 也能实时推帧到网页
3. **NL → 结构化动作**：function call 而非自由文本
4. **脚本编译加速**：NL 执行成功后编译为脚本，下次直接跑
5. **漂移检测回退**：脚本回放失败时自动回退 NL 重跑并重编译

### 15.3 关键注意事项

1. **Playwright 同步 API 必须跑在独立线程**（不能在 asyncio 事件循环线程中）
2. **CDP screencast 必须逐帧 ack**（否则 Chromium 停止推送）
3. **VLM 图像需要缩放压缩**（降低 token 消耗）
4. **知识库是跨用例共享的**（越跑越稳的核心机制）
5. **人工审核是硬约束**（AI 生成物一律 draft，通过后才 active）
6. **双框架兼容**（CSS 选择器同时考虑 Ant Design 和 Element UI）
7. **面包屑到达校验**（导航后必须验证真正到了目标页）
8. **环境变量控制无头模式**（`PW_HEADLESS=0/1` 覆盖配置文件）

### 15.4 大模型接入要求

- 必须兼容 **OpenAI Chat Completions API** 协议
- 必须支持 **function calling**（用于步骤解析和用例生成）
- 必须支持 **多模态图像输入**（用于 VLM 视觉定位和断言）
- 推荐模型：GLM-4V 系列、GPT-4V、Qwen-VL 等支持上述能力的模型

### 15.5 配置优先级规则

```
DB 默认记录 > 环境变量 > config.yaml

具体：
- 测试数据（URL/账号）→ 读 DB TestEnv 默认记录
- LLM 配置 → 读 DB LLMConfig 默认记录
- 浏览器配置 → 读 config.yaml（PW_HEADLESS 环境变量可覆盖）
- 首次空库 → 从 config.yaml 播种一条默认环境
```

## 十七、安全设计

| 安全点 | 实现方式 |
|--------|---------|
| API Key 存储 | Fernet 对称加密存库，接口返回一律掩码（`sk-****`） |
| 密钥使用 | 仅 Worker 执行时后端解密注入，不下发前端 |
| 破坏性操作防护 | `allow_risky` 开关 + `RISKY_KEYWORDS` 自动过滤 + 人工审核 |
| AI 生成物管控 | 一律 draft 状态，人工 approve 后才可执行 |
| 环境隔离 | 测试环境配置化，不同环境独立 URL/账号 |
| 密码存储 | 测试账号密码加密或环境变量注入 |
